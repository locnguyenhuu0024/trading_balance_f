## Multi-target attempts and outcomes

One confirmation/idempotency key/connection lease and fence belongs to the operation. Claim marks only the first actually attempted target; before every subsequent marker/send recheck live exact fence, session authority, versions, active connection, fresh identity/mode/filter/position bindings. A lease renewal may extend only an already-live exact claim; never resurrect an expired fence. Persist each target ATTEMPT_STARTED/pre_send_at before network send. Do not mark all targets attempted upfront.

Stop on FAILED, PARTIAL, UNKNOWN or lost authority/fence; never automatically resume an untouched tail. Untouched targets become CANCELED with safe not-sent reason and null pre_send_at. Preserve any already-marked uncertain target as UNKNOWN. Aggregate precedence: any unresolved marked target => UNKNOWN; all targets proven success => SUCCEEDED; otherwise any proven effect/success/partial => PARTIAL; otherwise FAILED. An operation with a submitted-but-unproven effect cannot be FAILED solely because authority was lost.

Close-all SUCCEEDED additionally needs fresh complete same-scope position evidence: every prepared symbol flat and no unexpected nonzero position. Unexpected exposure yields PARTIAL, no automatic additional write. Failure/unavailability of this final proof preserves UNKNOWN. A completed partial close is SUCCEEDED only with exact intended fill and expected residual exposure; partial execution is PARTIAL.

ACK is acceptance only. Validate returned native symbol/client ID/order ID/side/original quantity; malformed or inconsistent evidence yields UNKNOWN. Prove closes from original order lookup plus fresh position state; disappearance alone is insufficient. Filled close with exact intended executed quantity and expected remaining same-sign exposure proves success; partial terminal fill retains exact executed/residual quantities as PARTIAL. Contradictory order/position evidence stays UNKNOWN. Cancel CANCELED with zero fill => SUCCEEDED; partially filled then canceled => PARTIAL; already FILLED => FAILED cancellation while retaining FILLED state/quantity/exposure. Missing or malformed lookup remains UNKNOWN.

Timeout/disconnect, malformed/oversized responses, -1006/-1007, unknown 503/unrecognized server errors and duplicate -4116 => UNKNOWN, lookup original identity, zero resubmission. Exact documented 503 Service Unavailable/Internal Failure and -1008 => definite FAILED, no retry. -2022/-4118 reduce-only conflicts => FAILED, no unrelated cancellation. -2013 lookup absence does not prove failure. Safe classification contains bounded status/native code/category only; raw messages/payloads never enter errors/results/logs.

Result GET remains read-only. Reconcile claims a fresh fence, verifies original owner/UID and queries only marked unresolved targets; no new ID, send or tail resume. Publication requires exact live fence and durable marker; stale callbacks cannot overwrite newer claims. Existing revoked/relinked same-owner recovery applies.
